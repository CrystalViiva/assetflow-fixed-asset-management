# System architecture

## Authority and request path

The transactional source of truth is Django and PostgreSQL. The React/TypeScript application authenticates against the versioned REST API and uses explicit DTOs and repositories. It does not compute accounting truth or emulate domain state from browser caches.

The backend request path is:

HTTP API → view and permission policy → serializer boundary → domain service → selector/query layer → ORM and PostgreSQL constraints

Serializers validate and represent API data. Services own consequential transitions, transactions, audit-event creation, and invariant enforcement. Selectors keep common organization and department visibility rules in backend queries.

## Runtime components

| Component | Responsibility |
|---|---|
| React / TypeScript | Public landing and authenticated workflows; TanStack Query is scoped to user/session generation. |
| Django REST Framework | JWT authentication, tenant/RBAC enforcement, REST DTOs, domain service entry points, live dashboard and reporting APIs. |
| PostgreSQL | Authoritative organizations, users, assets, accounting ledgers, workflows, audit history, assurance state, snapshots, export state, and analytics publication metadata. |
| Redis / Celery | Operational asynchronous work: assurance execution/recovery, report snapshots and exports, depreciation orchestration and maintenance tasks. |
| Private storage | Verification evidence and report export bytes. The application accesses content through authenticated endpoints; raw storage locations are not public links. |
| Airflow | Schedules and retries extraction of completed report snapshots. It does not implement domain rules. |
| PySpark | Validates versioned JSONL and transforms it into typed curated Parquet datasets. It does not mutate the transactional database. |

## Domain boundaries

Acquisition/capitalization establishes cost basis. Depreciation entries form the posted ledger and update asset balance snapshots transactionally. Assignments own custody; transfer completion owns department/location placement. Maintenance creates operational records and does not capitalize its costs or change depreciation balances. Physical verification records observations/exceptions without silently correcting master data. Assurance evaluates frozen inputs and publishes findings only after successful evaluation. Disposal records the controlled derecognition snapshot.

Audit events are generated by domain services and are immutable through ordinary application ORM operations. This is application-level protection, not cryptographic tamper evidence.

## Read and analytics models

- A live report is a current query.
- A report snapshot captures ordered rows and schema version in a repeatable-read capture.
- An export is generated from a completed snapshot and privately stored.
- The dashboard is a bounded live PostgreSQL aggregate.
- Curated marts are asynchronous batch outputs from snapshot-based data.

These surfaces intentionally have different freshness and historical semantics. See [the engineering decisions](engineering-decisions.md), [reporting guide](F9-reports-snapshots-exports.md), and [data pipeline guide](analytics.md).

## Browser architecture

The public landing and login routes do not request tenant data. Authentication bootstrap protects private routes. The frontend keeps the access token in memory, the rotating refresh token in session storage, and fences user-scoped query results with a session generation. Route screens and large features load on demand to keep the initial shell small.
